# How soon can an AIS model recognize the start of apparent fishing?

**X50 · Foundation models for AIS activity recognition · Conditional on event labels · 5 November 2026**

An analyst monitoring apparent fishing must wait for enough movement to distinguish a fishing pattern from a vessel slowing or turning in transit. For a vessel that reports every ten minutes, two confirming messages can mean a twenty-minute wait. **At the same false-alert rate per labelled vessel-day, can a pretrained time-series encoder adapted to AIS detect more annotated fishing episodes within 30 minutes of onset than a motion rule or compact causal classifier?** The 30-minute horizon is a proposed experimental choice. The reference event is the change in the historical activity annotation. Actual gear deployment time and legality are outside the evidence.

**Candidate gap.** This bounded search found direct precedents for pretrained movement representations, streaming detection and confidence thresholds. It did not establish how the *delay–false-alert trade-off* changes with AIS cadence and ambiguous event boundaries on the same independently held-out vessels. The hypothesis is that conditioning a detector on elapsed observation time improves event recall at the same false-alert budget. A plausible rival is that the improvement disappears once a simple speed/turn rule also gets a tunable waiting time. [X29](x29-fishing-classification-shift.md) instead predicts vessel type under changes in fleet mix. [X47](x47-radar-vessel-behaviour-from-tracks.md) studies sensor transfer to radar.

## Data and model feasibility

- Start with existing labelled fishing-vessel tracks from the GFW training repository. The release specifies CC BY 4.0, NumPy files, Git LFS and a track/label join. Inspect individual files for vessel identity, timestamps, annotation coverage, ambiguous labels, continuous negative observation time and usable transitions before promising a sample size. Compute storage from the needed LFS objects. Preserve attribution and report aggregate errors. [Data and preparation instructions](https://github.com/GlobalFishingWatch/training-data)
- Use the MIT-licensed MOMENT-1-small general time-series foundation model as a frozen encoder on trailing windows of speed and course change. Add a small trainable activity or stopping head. Resample using past messages only, carry a missingness mask, and cache prefix embeddings. Compare the pretrained encoder with a random-weight equivalent and a compact trained temporal convolutional network. [MOMENT model card and classification interface](https://huggingface.co/AutonLab/MOMENT-1-small)
- ATLAS is a supervised maritime specialist and the strongest operationally relevant comparator here. Ai2 reports releasing its weights and code. The documented service launch calls for Google Cloud credentials, so verify an offline checkpoint and preprocessing path. Map fishing to the positive class and record whether the published post-processing is reproduced. If only the raw head runs, identify that comparison explicitly. [Ai2 release](https://allenai.org/blog/atlantes) · [Repository setup](https://github.com/allenai/atlantes)

## Experimental design and individual ownership

Replay each complete held-out vessel track in timestamp order. Count an onset only when an explicitly labelled non-fishing interval precedes a labelled fishing interval. The last negative and first positive observations bracket the transition. Report delay from both bounds and repeat after restricting boundary widths. Exclude unknown time from the false-alert denominator. Match each alert to at most one event, fix a refractory period using validation vessels and report unmatched alerts, missed events, and evaluable vessel-hours. An episode already underway when observation begins cannot supply onset time.

| Member | Test and ablation | Individual result |
|---|---|---|
| A — does pretraining help early recognition? | Fit identical heads on frozen pretrained and random features. Compare with a speed/turn rule, a supervised causal network and ATLAS where reproducible. Vary the number of labelled training vessels. | Event recall by 30 minutes and label-budget curves on unseen vessels. |
| B — how much delay comes from sampling? | Replay the same held-out events at original cadence and with paired message thinning. Compare mask-only features with elapsed-time-aware adaptation. Keep the original annotations fixed and report natural and simulated cadence effects separately. | Change in recall and delay by cadence and by boundary width, with a matched waiting-time rule as control. |
| C — when should the model raise an alert? | Compare a fixed probability threshold, consecutive-message confirmation, confirmation by elapsed minutes and a learned stopping head. Set thresholds on separate calibration vessels at a common false-alert budget. | Recall–delay–false-alert curves and vessel-bootstrap intervals. Include missed events in deadline recall so a method cannot look fast by detecting only easy episodes. |

Assign whole vessels before making training windows. Use earlier periods for fitting and later disjoint vessels for the final test where the date range permits. Stratify by gear only where independent vessel and event counts support it. Audit dates against checkpoint training records. Atlantes reports activity training from January 2022 through June 2024. Check whether the evaluation tracks predate or overlap that interval and whether the same vessels recur. A held-out downstream vessel may still have appeared in pretraining. [Atlantes training data](https://arxiv.org/html/2504.19036v1)

**Module decision.** Second choice behind [X49](x49-ais-foundation-forecast-stale-tracks.md). X50 has a clear user, an offline prototype and three experiments suited to a shared GPU with cached features. Its main risk is whether the public annotations support *timing* and an honest false-alert denominator. Strong segment accuracy cannot repair missing event boundaries. Even a null result can quantify the delay caused by cadence and show where a simple confirmation rule suffices.

**Before shortlisting.** Spend the first pilot week joining a small track/label subset. Tabulate distinct vessels, bounded onsets, boundary widths and explicitly labelled negative hours per split. In week two, replay a motion rule and one locally loaded checkpoint and estimate whether the available events and vessel-hours yield useful precision at the chosen alert budget. Reduce the gear scope if support is thin. If onset brackets or negative exposure are inadequate, defer X50. Buying AIS records or requesting new expert labels would violate the project's resource assumptions. With data suitability, comparator access and novelty still provisional, the [module rubric](../../../research-module-and-team-criteria.md) score is withheld.
