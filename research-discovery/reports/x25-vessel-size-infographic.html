02 / Published starting pointTransOSS · auxiliary information ↗

Size is already used. Its reliability is the question.

TransOSS combines visual features with approximate size from crop dimensions and GSD. The paper acknowledges that crops are not exact ship boundaries. Whether this causes important matching errors remains to be tested.

05 / A fair test

Keep the visual model and gallery fixed.

Visual onlyDoes size help at all?
Visual + fixed sizeConventional size fusion.
Visual + uncertain sizeThe proposed intervention.

Measure rank-1 accuracy (the top match is correct), mAP (ranking quality), and wrong-match risk versus coverage. Hold out complete identities; keep duplicate crops together. Test both optical→SAR and SAR→optical, clean inputs, controlled crop padding and similar-sized galleries. Keep GSD consistent when resizing.

Before choosing this topic: inspect usable size/GSD fields, reconcile dataset identity labels, check checkpoint training overlap and compare close methods such as MOS and SDF-Net. HOSS archive access is verified; size-feature loading and model performance are not.

Novelty remains unresolved. A useful negative result could show that visual-only features suffice or that ordinary size fusion is already robust.

Claim boundary: this evaluates visual vessel identity. It does not establish registration, intentional AIS shutdown or illegality. Crop changes are controlled tests, not proof of naturally occurring size errors.
